# skill-evaluator · C4 提交自动评审器

> 一句话：**输入一个装着 C4 提交的文件夹，输出一份评审报告——谁交了、缺什么、四条件达不达标、预测多少分。**

---

## 为什么需要它

C4 要求每位同学交五件东西（skill说明 / 可执行内容 / demo / 教学说明 / AI日志），
还要同时满足四个条件（可复用 / 可执行 / 可验证 / IO 明确）。

一个班五十人、每人五份文件，**老师没法一份份看**。而同学在下发之前，
也没法知道"我这个到底算不算合格"。

这个工具把那件事自动化：**扫描 → 完整性 → 四条件 → 报告**。

---

## 什么时候用 / 不用

| 用 | 不用 |
|---|---|
| 收完作业要盘点谁交了、缺什么 | 评审单份提交的**语义质量**（"这个想法好不好"）——本工具不做价值判断 |
| 下发前想先自己过一遍评分口径 | 需要执行被评审代码来验证功能——**本工具只读文件，绝不执行任何代码** |
| 需要一份可复核的班级总览 | 非技能类作业（论文、Web App 等有各自的口径） |

## 快速开始

```bash
# 零依赖：只用 Python 标准库，Python ≥ 3.9
python scripts/skill_evaluator.py <提交文件夹>

# 写成报告文件
python scripts/skill_evaluator.py ./submissions --out 评审报告.md

# 给别的程序用
python scripts/skill_evaluator.py ./submissions --json
```

跑一遍自己的可靠性基准：

```bash
python scripts/run_benchmark.py --all
```

## 工作流程

### L1 · 文件采集与识别

扫描文件夹，按 `姓名拼音_C4_内容描述.扩展名` 识别作者并分组。

**识别不到作者时不会丢文件**——回退到"按父目录名推断"，并在报告里如实标注
「未按 `_C4_` 规范命名」。实在归不了属的，放进「（未识别作者）」组。
**丢掉比认错更糟：丢掉会让一个真交了作业的人变成"没交"。**

### L2 · 提交完整性检查

五个必须文件逐个查：文件名匹配 + 内容信号双重判据。
（只看文件名会漏掉"文件名叫 a.md 但内容是教学说明"的人；只看内容则会误判。）

输出：**✅ 齐全 / ⚠️ 部分缺失 / ❌ 严重缺失**

### L3 · 四条件质量评审

| 条件 | 规则层查什么 |
|---|---|
| **可复用** | 有安装/使用步骤、声明了环境与依赖、有泛化说明；**以及两条否决项**——写死个人绝对路径、依赖私有资源 |
| **可执行** | 有没有能跑的东西；`.skill` 包结构是否完整（SKILL.md 必须在顶层）；有没有可复制的 prompt/命令 |
| **可验证** | 有没有输入→输出示例、有没有测试/自检、有没有可量化指标、有没有 demo 产物 |
| **IO 明确** | 有没有"输入\_\_\_\_，输出\_\_\_\_"式的一句话；输入的类型与输出的形态有没有说清 |

### 报告

Markdown 报告：总览表（按预测分排序）+ 每人的详细页（否决项 / 五个必须文件 / 四条件逐条依据 / C4 维度预测分）。

## 关键设计决策

### 决策 1：规则层只判「确定性才能判准的」，语义的**刻意不判**

| 层 | 判什么 | 为什么 |
|---|---|---|
| **规则层** | 文件结构、命名规范、包完整性、**写死的绝对路径**、私有资源依赖、计数 | 这些 LLM 也能做，但会不稳定（同一输入两次可能不同）。而"可复用"的核心风险恰恰是绝对路径与私有依赖——**这类检查必须确定性，否则一次误判就是冤枉一个同学** |
| **LLM 层**（可选） | "IO 说得清不清楚"、"教学文档是不是真能教会人"、"复盘是不是真反思" | 写正则去猜只会得到一堆假报。这些列在 `references/rubric.json` 的 `semantic_checks` 里 |

**两层边界写在判据表里**，所以评审结果可以被质疑：
哪一条是规则判的、哪一条是模型判的，一望可知。

### 决策 2：输出分**对齐 C4 的真实 rubric**，不自造一套

如果评审器自己造一套分，谁也说不清它评得准不准。
对齐之后，就能拿它的**预测分**与**真实 C4 得分**做对照——**评审器本身也就可验证了**。

| C4 维度 | 满分 | 本工具怎么预测 |
|---|---|---|
| skillQuality 技能质量 | 25 | 由四条件等权合成 |
| teachability 可教性 | 20 | 教学说明的存在性 + 内容信号 |
| artifactCompleteness 产物完整性 | 15 | 五个必须文件的齐全度 |
| aiUsage AI 使用质量 | 20 | AI 日志的存在性 + 内容信号 |
| reflectionQuality 复盘质量 | 20 | 全文扫"失败/踩坑/改进"信号，**上限刻意压到 60%** |

### 决策 3：否决与扣分是两回事

- **否决项**（写死绝对路径、依赖私有资源、没有任何可执行产物）→ 整体判**不合格**，
  并按 C4 原文「四条件必须**同时**满足」，把技能质量这一维度**判 0**。
- **扣分项**（如 `.skill` 里 SKILL.md 埋在子目录）→ 只扣分，不判死刑。
  它可能在某些宿主里仍能工作，**判死刑太重**。

> 这条边界是刻意的。一个全都有罪/全都没罪的评审器没有用——
> 它必须能区分"这个别人根本跑不起来"和"这个有点小毛病"。

## 边界情况

| 情况 | 行为 |
|---|---|
| 文件夹是空的 | 退出码 2，明确提示，不产出一份空报告 |
| 文件名没有 `_C4_` 标记 | **不丢**，回退推断并在报告中标注 |
| 文件是图片/视频 | 只按扩展名参与"demo"判定，**不尝试读内容** |
| `.docx` | 用标准库解 zip 读 `word/document.xml`——不装第三方包 |
| `.pdf` | **不支持正文提取**（标准库做不到，不引依赖）。如实记入已知限制 |
| `.skill` 是 zip 还是 tar.gz | 两种都试；解不开则报"无法解包" |
| 提交里带可执行文件 | **绝不执行**（安全边界），只做静态检查 |

---

## 它不做什么

- ❌ **不做价值判断**。它不评"这个技能的想法好不好"，只评"它作为一份提交是否完整、是否可被别人用起来"。
- ❌ **不执行任何代码**。
- ❌ **不联网**。
- ❌ **不打最终分**。它给的是**预测分**，且靠语义判断的维度（可教性、复盘质量）规则层只能给下限。
- ❌ **不替代人工复核**。它把"五十人 × 五份文件"压成一份总览，让人只看需要细看的那几份。
